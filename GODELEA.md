# Godelea: redrawing every picture of the game

Godelea is a logic puzzle game for phones (Godot, Spanish), at
`../mathrpg/godelea`. Every picture it shows is being redrawn by hand. This
repo turns photos of those drawings into the exact files the game expects.

## What to draw: the game's own list

The game publishes the list of every picture it uses today. It is the contract:

- `../mathrpg/godelea/assets/art/ART_MANIFEST.json`: one entry per file, for
  tools and agents. For each picture:
  - `file`: name and folder, exactly as the game loads it (`characters/robot.png`).
  - `width`, `height`: size of today's picture. Keep the proportions; bigger is fine.
  - `transparent`: whether it needs a transparent background.
  - `frames`, `fps`, `frame_width`: animations, a horizontal strip of square
    frames (same number of frames).
  - `shows`: what it is (`bread: pan (piece r in La panadería)`).
  - `used_in`: where the game uses it.
  - `redraw`: true for the pictures to draw. `glyphs/` are generated by the
    game, and unused files are listed but need no drawing.
  - `rules`: the folder's rules. Examples: buttons are 9-slice and keep 12 px
    on each side; map terrain tiles must join without seams; characters stand
    with their feet on the bottom edge; story pictures must read at 40 px; no
    text inside pictures.
- `../mathrpg/godelea/assets/art/ART_LIST.md`: the same list for people,
  grouped, with a box to tick.
- The current pictures are in `../mathrpg/godelea/assets/art/`, in the same
  folders. Look at them to see what each one is and how it is framed.

The list is generated from the game. If the game changed (a new island, new
pictures), regenerate it before relying on it:

```sh
cd ../mathrpg/godelea && python3 tools/art_manifest.py
```

## How drawings get into the game

1. The artist draws on paper and puts the photos in the Google Drive folder
   «godelea arte» (path in `drawings/godelea.json`).
2. `drawings/godelea.json` says which drawing of which photo is which game file.
3. `node tools/godelea.js` cuts each drawing, cleans it and fits it to its
   file (size, transparency, placement per folder: `src/godelea.js`). The
   results go into `library/godelea/art/`, a folder that mirrors the game's
   `assets/art`, plus a review sheet (today's picture next to the drawing).
4. Check them against the game's list:

   ```sh
   python3 ../mathrpg/godelea/tools/check_art.py library/godelea/art
   ```

   It flags wrong names, proportions, missing transparency and animation
   strips with the wrong number of frames, and says how many are still to
   draw.
5. Only when the artist agrees, copy them into the game:

   ```sh
   python3 ../mathrpg/godelea/tools/check_art.py library/godelea/art --install
   ```

   Then, in `../mathrpg/godelea`, run `godot --headless --path . --import` and
   `godot --path . -s res://test/render_glyphs.gd` (the small pictures inside
   texts are rendered from the new art). Then build a new APK (see the
   game's README).

## Rules that matter most

- Same file name and folder as in the list; never invent new names (the game
  finds pictures only by name).
- Same proportions as today's file; transparent PNG unless the list says otherwise.
- Animations: a strip of square frames, as many as the list says.
- One style for the whole game. Pictures must read small on a phone: thick
  shapes, no text.
- Do not draw `glyphs/` (generated) or files with `redraw: false`.
